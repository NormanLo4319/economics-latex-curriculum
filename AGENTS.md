# Skill Routing Rules

1. **Always Apply Governance First (`core-skill`):** For all economics coursework, slides, graphs, assessments, and demos, follow `core-skill` (zero fabricated stats/citations/FRED codes, clarification-first on ambiguity, FERPA/17 U.S.C. § 102(b) compliance, Chiang/Krugman & Wells alignment, and Ample-Reserves policy).
2. **Authoring vs. Auditing Split:**
   - **Create** readings, case studies, and 4-part module sections -> `econ-curriculum-author` + `math-skill`.
   - **Create** 16:9 lecture decks (6–8+ slides) -> `econ-presentation` + `econ-visualization-reviewer`.
   - **Audit/Patch** existing chapters, math proofs, or CLOs -> `econ-professor-auditor` (patch-only report).
   - **Create/Audit** coordinate graphs, curves, or SVG/Matplotlib/TikZ charts -> `econ-visualization` (generate) and `econ-visualization-reviewer` (audit).
3. **Assessments vs. Empirical Research:**
   - **Design/Audit** Tier 1–4 questions, clean parameterizations, distractor rationales, or Universal Question JSONs -> `econ-assessment-auditor` + `math-skill`.
   - **Design/Run** econometric identification (DiD, IV, RDD, panel FE), FRED/World Bank data pulls, R/Stata/Python models, or AEA/Beamer outputs -> `economist`.
4. **Software Engineering Isolation (`superpower`):** Use `superpower` (brainstorming, specs, atomic plans, TDD, root-cause debugging) strictly for software/web-app code and engineering workflows—not for economics prose or econometric modeling.
